# Notchwave 사용 및 연결 가이드

[프로젝트 소개와 디자인 미리보기로 돌아가기](../README.md)

Spotify · 캘린더 · 배터리 · AI 사용량을 화면 상단에서 확인하는 macOS 앱입니다.

## 실행과 화면

[빌드 안내](../README.md#빌드와-실행)에 따라 만든 `Notchwave.app`을 엽니다. Dock 아이콘 없이 메뉴 막대의 파형 아이콘으로 동작합니다.

- 시스템 디스플레이 배치의 **메인 디스플레이**를 사용합니다. 현재 키보드 포커스나 노치가 있는 화면을 우선하지 않습니다.
- 메인 화면에 노치가 있으면 기존 검은 노치 디자인을 사용합니다.
- 노치가 없으면 **메뉴 막대 중앙 안쪽**에 Glass 캡슐로 표시합니다. 막대 높이에 맞추고 화면 위쪽에 2pt 여백을 둡니다. 펼치면 그 위치에서 아래로 확장됩니다.
- 실제 바탕화면과 뒤쪽 창을 반영하는 반투명 소재를 사용하며, macOS 26 이상은 Clear Liquid Glass를 함께 적용합니다. 시스템의 투명도 감소 설정은 존중합니다.
- 연결 화면에서도 같은 반투명 배경을 사용하며, 직접 입력 때문에 창이 활성화되어도 배경 소재의 활성 상태를 유지합니다. 서버 선택만 할 때는 다른 앱의 키보드 포커스를 가져오지 않습니다.
- 기본 캡슐은 내용 없이 유지합니다. Spotify 곡이 있으면 일시 정지 중에도 앨범 사진·재생 상태 표시, 배터리 부족 시에는 약 7초 동안 기기명·잔량이 나타납니다. 배터리 알림이 재생 표시보다 우선하며, 끝나면 원래 상태로 돌아갑니다.
- 마우스를 올리거나 클릭하면 펼쳐집니다. 마우스를 빼면 접히고, 밖을 클릭하면 고정 상태도 해제하며 닫힙니다. 핀은 마우스를 옮겨도 유지하는 기능입니다.
- 일정 편집 중에는 마우스를 옮기거나 다른 앱을 클릭해도 입력 화면을 유지합니다.
- 화면 연결·해제, 주 화면 변경, 잠자기 복귀 시 위치를 다시 계산합니다.

## Spotify

**Spotify 연결** 후 macOS의 제어 권한을 허용합니다. Mac용 Spotify의 현재 곡·앨범 사진·재생 상태를 읽고 이전/다음·재생/일시정지·재생 위치를 제어합니다. 웹 플레이어나 휴대폰에서만 실행 중인 Spotify는 지원하지 않습니다. 일시 정지해도 Spotify가 실행 중이면 캡슐의 곡·앨범 표시를 유지하고 파형과 진행 표시만 멈춥니다. Spotify를 종료하면 음악 표시가 사라집니다.

## 캘린더

**주간 요약**과 **시간표**, 일정 생성·수정 기능을 제공합니다.

**캘린더 연결**에서 전체 접근을 허용합니다. macOS가 동기화한 캘린더 계정의 일정을 표시합니다. 날짜마다 시간순 카드와 더 보기 버튼을 제공하며, 날짜를 누르면 하루 전체 목록이 열립니다.

- 상단 **+**, 하루 목록의 **일정 추가**로 새 일정을 작성합니다.
- 기존 일정 선택 → **수정**에서 제목, 시작·종료, 종일, 캘린더, 장소, 메모를 편집합니다.
- 저장할 때만 실제 캘린더에 반영합니다. 취소하면 작성한 변경을 버립니다.
- 종일 일정의 마지막 날은 포함하는 날짜입니다. 반복 일정은 선택한 회차만 수정합니다.
- 구독 등 읽기 전용 일정, 다른 사람이 초대한 일정은 편집하지 않습니다. 반복 일정·참석자 일정의 캘린더 이동은 지원하지 않습니다.
- 외부에서 변경·삭제된 원래 일정은 덮어쓰지 않고 다시 열도록 안내합니다.
- 예시 일정 생성·수정은 메모리에서만 동작하며 실제 캘린더를 바꾸지 않습니다.

## 배터리

macOS의 전원 목록에서 MacBook과 시스템이 잔량을 제공하는 액세서리를 표시합니다. AirPods와 케이스, 트랙패드, 키보드, 헤드폰 등의 아이콘을 구분하고, AirPods의 좌우 잔량과 충전 표시도 지원합니다.

- **21–100%: 초록색**, **0–20%: 빨간색**. 확인되지 않은 잔량은 `—`로 표시합니다.
- 충전 중이 아닌 기기가 **50% 이하**가 되면 캡슐/노치에 약 7초 동안 알립니다. 시작할 때 이미 낮은 기기도 한 번 알립니다.
- 반복 알림을 막기 위해 기기별 알림 여부를 기억합니다. **55% 초과**로 회복하면 다음 알림을 허용합니다.
- 여러 기기는 차례로 알립니다. 알림을 클릭하면 배터리 탭이 열립니다.
- 충전이 시작되면 기기 아이콘·이름·‘충전 중’과 원형 잔량 게이지를 약 7초 동안 표시합니다. 원형 게이지는 0에서 현재 잔량까지 차오르며, 동작 줄이기 설정에서는 즉시 표시합니다. 색은 기존 잔량 색(20% 이하 빨강, 50% 이하 노랑, 그 이상 초록)을 유지합니다.
- 시작 시 이미 충전 중인 기기는 알리지 않습니다. 이후 충전 시작이나 충전 중인 새 기기 연결을 감지하며, 연결 해제 후 재충전하면 다시 알립니다.
- 약 3초마다 새로 읽습니다. 시스템이 제공한 최근 값이므로 기기 자체의 업데이트 주기를 따릅니다. macOS에 충전 상태를 제공하지 않는 기기는 충전 알림을 지원하지 않습니다.

- 액세서리는 Apple의 공개 소스 헤더에 정의된 비공개 IOKit `IOPSCopyPowerSourcesByType(0)`를 동적으로 사용합니다. 사용할 수 없는 OS에서는 공개 전원 API로 내장 배터리를 읽습니다. 임의의 기기에 연결하거나 배터리 값을 변경하지 않습니다. 이 호환성 경로는 OS 업데이트에 따라 달라질 수 있고 App Store 배포용으로 보장되지 않습니다.

## AI 응답·승인 알림

**AI 사용량** 안의 **Codex / Claude** 탭에서 각 서비스를 연결합니다. Codex의 **완료·승인 알림**, Claude의 로컬·원격 연결에서 알림을 관리합니다. 상단 종 모양 버튼 또는 메뉴의 **AI 알림 보기**는 받은 알림을 확인하는 보관함입니다. 기존 훅, 권한 설정, Claude 사용량 상태 표시줄은 보존하며, 해제하면 Notchwave가 등록한 명령만 제거합니다.

AI 알림 미리보기 메뉴는 표시하지 않습니다. 보관함에 완료 또는 승인 알림이 하나라도 남아 있으면 고정 핀 옆에 시스템 강조색(현재 초록색)의 `bell.badge`와 아래 화살표를 표시합니다. 보관함을 열어도 표시는 유지되며, 알림이 모두 정리되면 회색 종으로 돌아옵니다.

알림이 남아 있어도 캡슐에 마우스를 올리거나 일반 캡슐을 눌러 펼치면 마지막으로 선택한 화면을 유지합니다. 알림 보관함은 종 아이콘이나 **AI 알림 보기** 메뉴로 직접 열 수 있습니다. 표시 중인 알림 배너를 누르면 해당 대화로 이동합니다.

알림이 처음 나타날 때 캡슐 높이를 충전 알림과 같은 56pt로, 너비를 평소 알림보다 24pt 넓게 키웁니다. 큰 아이콘·프로젝트 이름·시스템 강조색 테두리를 약 2.5초 동안 표시한 뒤 기존 작은 알림 크기로 돌아옵니다. 유지 중인 같은 알림은 반복해서 커지지 않습니다. 동작 줄이기 설정에서는 크기 전환 애니메이션을 생략합니다.

- 응답 종료 시 5초 배너를 표시하고 음악 화면으로 돌아옵니다. 일시 정지 중에도 배너가 끝나면 음악 화면으로 돌아옵니다. 표시할 음악이 없을 때 도착한 Codex 알림은 빈 캡슐에 계속 남습니다. 새 Codex 알림이 오면 교체하며, 알림 확인·삭제, 해당 작업 재개 또는 음악 표시 시작 시 고정을 해제합니다. 충전 등 다른 알림이 잠깐 표시된 뒤에도 다시 나타납니다. 응답 종료가 전체 작업의 성공을 뜻하지는 않습니다.
- 권한 요청은 5초 배너 후 대기 배지로 남습니다. 음악이 없을 때 도착한 Codex 권한 요청은 캡슐에 유지합니다. 요청한 도구 실행, 다음 사용자 입력, 응답 종료 또는 세션 종료 시 정리합니다. 직접 지우기도 가능합니다. 캡슐에 고정된 알림을 제외한 오래된 대기는 한 시간 후 정리합니다.
- Codex 알림에는 해당 대화의 제목을 표시하며, 알림과 보관함 항목을 누르면 `codex://threads/<대화 ID>` 링크로 그 대화를 엽니다. 원격 대화는 확인된 `hostId`를 함께 전달하고, 클릭 시 연결 대상을 다시 확인합니다. 긴 제목은 말줄임하며 마우스를 올리면 전체 표시 제목을 볼 수 있습니다. Claude Code는 기존처럼 감지된 앱이나 터미널을 엽니다. 승인은 원래 앱에서 진행합니다.
- 대화 제목과 호스트는 Codex 홈의 `sqlite/codex*.db` 대화 목록에서 읽기 전용으로 조회합니다. 예전 버전에서는 `session_index.jsonl`의 제목을 사용합니다. 대화 본문·명령·인증 정보는 조회하지 않으며, 이 메타데이터 구조가 바뀌거나 제목을 찾지 못하면 프로젝트 이름을 표시합니다. 조회한 제목과 호스트는 알림과 함께 메모리에만 보관합니다. 자동 제목 생성이 늦으면 잠시 다시 확인합니다.
- 완료 내역 20개와 승인 대기 최대 50개를 메모리에 보관합니다. 기기 알림 중에는 AI 배너 표시 시간을 연장합니다.
- Codex에서 해당 대화를 확인해 읽음 상태가 되면 완료 알림을 캡슐·보관함에서 자동으로 지웁니다. 노치 알림 대신 Codex의 사이드바나 다른 창에서 대화를 열어도 동기화하며, 남은 알림이 없으면 종 아이콘도 기본 상태로 돌아갑니다. 로컬·원격 대화 모두 해당 호스트의 읽음 상태를 확인합니다. 승인 대기는 대화를 보는 것만으로 승인된 것이 아니므로 실제 작업 재개·종료 또는 직접 삭제할 때 정리합니다.
- 읽음 상태는 Codex 홈의 `.codex-global-state.json`에서 `electron-thread-read-state-v1`만 읽기 전용으로 확인합니다. 보통 다음 확인 주기(약 0.5초)에 반영되며 빠르게 확인한 알림은 몇 초의 안정화 시간을 둡니다. 상태가 없거나 형식이 바뀌었거나 계정·호스트가 모호하면 알림을 유지합니다. 내부 저장 형식을 사용하는 호환성 경로이므로 Codex 업데이트 후 보완이 필요할 수 있습니다.
- Codex 대화 완료는 이 Mac의 데스크톱 앱이 받은 완료 신호도 함께 확인합니다. 따라서 Mac에 완료가 도착한 SSH 원격 작업도 표시합니다. 다른 앱을 보고 있어도 알림 패널을 앞으로 표시하며 키보드 포커스는 옮기지 않습니다. 로컬 훅과 데스크톱에서 같은 완료가 전달되면 한 번만 표시합니다.
- **Codex 승인 요청과 CLI 알림은 `/hooks`에서 Notchwave 명령의 최초 검토·신뢰가 필요합니다.** 설정 등록과 실제 이벤트 수신은 별개입니다. 훅 신뢰나 샌드박스 정책을 자동 변경하지 않습니다. 훅은 연결 후 새 세션에서 사용합니다.
- 원격 완료 감지는 `~/Library/Logs/com.openai.codex`의 새 `received turn-complete` 기록에서 시각·대화 ID·응답 ID만 읽는 호환성 경로입니다. 과거 기록을 재생하지 않으며, 원본 로그와 응답 본문은 저장하지 않습니다. 공개 API가 아니므로 향후 Codex 로그 형식이 바뀌면 보완이 필요할 수 있습니다. Codex 앱에 완료 자체가 도착하지 않은 원격 작업은 감지할 수 없습니다.
- Claude 일반 채팅이 아닌 Claude Code의 공식 훅을 사용합니다. SSH 원격 Claude Code는 아래의 **원격 Claude** 연결을 사용합니다. 원격 Codex의 승인 요청은 별도 전달 연결이 필요합니다.

훅은 앱 실행 파일의 `--notchwave-ai-event codex|claude`로 최소 메타데이터를 전달합니다. 로컬 수신함에는 제공자·세션 ID·프로젝트 폴더명·이벤트 종류·도구 이름·시각·앱 식별자만 저장합니다. 명령 내용, 응답 본문, 대화 기록과 자격 증명은 저장하지 않습니다. 읽은 파일은 삭제하며 앱이 꺼져 있을 때도 최대 200개로 제한합니다. 1분보다 오래된 이벤트는 다시 알리지 않습니다.

공식 문서: [Codex Hooks](https://learn.chatgpt.com/docs/hooks), [Claude Code Hooks](https://code.claude.com/docs/en/hooks).

### Ghostty · SSH · tmux의 Claude 알림

**AI 사용량 → Claude → 연결 버튼 또는 +**에서 **로컬** 또는 **원격**을 선택합니다. 모든 연결 화면은 노치 패널 안에 표시하며 별도 창을 열지 않습니다. 로컬은 이 Mac의 Claude Code 연결을 설정합니다. 원격을 선택하면 `~/.ssh/config`에서 읽은 서버 목록과 체크 상자가 나타납니다. 여러 서버를 선택한 뒤 **추가**를 누르세요. 이미 연결된 서버는 체크돼 있고, 이를 해제한 뒤 **적용**을 누르면 연결을 해제합니다. 체크만 바꾸거나 닫으면 실제 설정은 바뀌지 않습니다. 로컬과 원격은 함께 사용할 수 있습니다. 연결한 서버는 Claude 탭의 하위 탭으로 표시하며 서버별 계정과 사용량을 따로 조회합니다.

목록 새로고침과 **수동으로 추가**를 제공합니다. 직접 입력도 노치 안에서 진행하며, 입력한 서버를 목록에 넣은 뒤 **추가**를 눌러 연결합니다. `Include`로 나눈 설정도 읽고 `Host *` 같은 와일드카드와 중복 항목은 제외합니다. 목록 조회는 설정만 읽으며 `Match exec`나 접속 명령을 실행하지 않습니다. 원격 서버에는 Python 3.8 이상, Mac에는 기존 SSH 키 인증 및 확인된 호스트 키가 필요합니다.

- 원격 로그인 셸의 `CLAUDE_CONFIG_DIR`를 우선 사용하고, 없으면 tmux 전역 환경과 기본 `~/.claude` 순서로 설정 폴더를 확인합니다. 사용량 조회와 알림 등록·해제·수신에 같은 로그인 환경을 적용합니다. 완료·승인·재개 훅만 추가하며 다른 훅·권한·상태 표시줄은 보존합니다.
- `settings.json`이 홈 디렉터리 안의 본인 소유 dotfile을 가리키면 심볼릭 링크를 유지하고 대상 파일을 수정합니다. 최초 원본은 서버의 `~/.local/share/notchwave/settings-backups/`에 설정 대상별로 백업합니다. 예전 버전의 `settings-before-notchwave.json`도 그대로 보존합니다.
- 서버에서 이미 실행 중인 Claude 작업을 중단하거나 재시작하지 않습니다. 최신 Claude Code는 설정 파일 변경을 보통 자동으로 반영합니다. 이미 떠 있던 권한 요청은 소급해서 알리지 않으며, 다음 요청부터 확인하세요. 반영되지 않는 구버전은 작업이 끝난 뒤 기존 대화를 재개할 수 있습니다.
- SSH 연결과 실제 훅 등록 여부를 구분합니다. 선택된 설정에 Notchwave 훅이 없거나 비활성화돼 있으면 **알림 설정 확인 필요**를 표시합니다. Claude 사용량 탭의 **알림 다시 연결**로 등록을 복구하고 수신 연결을 재시작할 수 있습니다. 사용자가 설정한 `disableAllHooks`는 자동 변경하지 않습니다.
- Notchwave가 서버마다 별도의 SSH 연결을 유지합니다. Ghostty 창을 닫거나 tmux에서 detach해도 알림을 받으며 연결이 끊어지면 자동으로 재접속합니다. Mac이 잠들거나 Notchwave를 종료한 동안은 실시간 수신할 수 없습니다.
- 표시는 **서버명 · 프로젝트 폴더명**입니다. 응답 완료와 승인 요청을 노치와 보관함에 표시하고, 작업 재개 시 해당 알림을 정리합니다. Claude 대화 본문과 실행 명령은 읽거나 전송하지 않습니다.
- 원격에는 세션별 최신 상태를 최대 200개 보관합니다. 한 시간 이내의 상태만 읽으며, 1분이 지난 완료는 보관함에만 표시합니다. 이미 전달받은 알림 ID를 Mac에 저장하여 재연결·앱 재시작 때 같은 알림이 다시 뜨지 않게 합니다.
- tmux 작업의 알림을 클릭하면 원래 서버·pane가 남아 있는지 확인한 뒤 **Ghostty의 새 탭**에서 그 작업에 연결합니다. 기존 터미널 입력줄에 명령을 입력하지 않습니다. Ghostty 1.3 이상과 macOS 자동화 권한이 필요합니다. 기존 tmux 클라이언트를 강제로 끊지 않습니다.
- tmux 화면을 직접 읽었는지는 자동 판별하지 않습니다. 알림 클릭·수동 삭제·다음 사용자 입력으로 완료 알림을 정리합니다. 승인 대기는 실제 도구 실행·작업 재개·종료로 정리됩니다.
- 연결된 서버의 체크를 해제하고 **적용**을 누르면 그 서버의 Notchwave 훅과 Mac의 연결 목록만 제거합니다. 원격 작업은 유지합니다. 일부 서버가 연결에 실패하면 성공한 설정을 유지하고 실패한 항목만 다시 적용할 수 있습니다.

명령줄로 등록할 때는 프로젝트에서 `build/Notchwave.app/Contents/MacOS/Notchwave --link-remote-claude studio,research`를 실행합니다. 연결 목록은 Mac의 `~/Library/Application Support/Notchwave/AI Alerts/RemoteClaude.json`에 저장합니다. 원격 전달기는 앱 리소스에 포함된 `Resources/remote-claude.py`입니다.

검증: 프로젝트에서 `bash scripts/test.sh`를 실행하면 Swift와 Python 검사를 함께 실행합니다. [Ghostty 자동화](https://ghostty.org/docs/features/applescript), [tmux](https://man.openbsd.org/tmux).

## AI 사용량

**Codex / Claude** 탭으로 나누어 표시합니다. 탭을 바꾸는 동작은 연결 상태를 변경하지 않습니다. 처음 연결하지 않은 서비스에는 연결 안내 화면이 나타납니다.

### Codex

**Codex 연결** 후 기존 ChatGPT 로그인으로 남은 비율과 초기화 시간을 표시합니다. 알림도 함께 등록하며, 화면 하단 **완료·승인 알림**에서 별도로 켜고 끌 수 있습니다. 이미 설정한 사용량·알림 연결은 유지합니다.

설치된 Codex CLI의 공식 App Server `account/rateLimits/read`만 호출합니다. 데스크톱 앱의 `~/.config/codex` 인증이 있으면 우선 사용하며 `CODEX_HOME` 환경 변수가 지정됐다면 해당 경로가 우선합니다. 3분마다 갱신하며 새로고침으로 바로 확인할 수 있습니다. 실제 제공되는 한도 기간을 표시하고 API 키 전용 계정의 구독 한도는 추정하지 않습니다.

### Claude: 계정과 서버별 사용량

**Claude 연결 → 로컬 / 원격**으로 연결합니다. 원격은 Mac의 SSH 설정에서 서버를 선택합니다. 연결 후에는 **이 Mac / studio / research**처럼 위치별 하위 탭이 생기며, 각 탭에서 해당 위치의 계정 이메일·요금제와 한도를 확인합니다. 계정 정보가 없으면 임의의 계정명을 넣지 않습니다. **+**에서 연결을 추가하거나 관리합니다.

- Claude는 **사용한 비율**을 표시합니다. Codex는 기존대로 **남은 비율**을 표시하며 숫자 옆에 기준을 명시합니다.
- 5시간, 전체 주간, Fable·Sonnet 등 모델별 주간 한도를 서버가 제공하는 만큼 각각 표시합니다. 값이 실제로 0%인 한도는 유지하고, 제공되지 않는 한도는 만들지 않습니다.
- 조회 시각과 초기화 시간을 표시합니다. 이전 값은 이전 조회로 표시하며, 만료·로그인 없음·조회 제한·SSH 연결 실패는 별도 안내로 구분합니다.
- 원격에서는 **기본 `claude auth status --json`**으로 현재 계정을 확인합니다. 평소 터미널과 같은 로그인 셸을 거쳐 `.bash_profile`·`.zprofile`의 `CLAUDE_CONFIG_DIR`와 실행 경로를 반영합니다. 로그인 셸에 지정된 값이 없으면 tmux의 해당 환경 변수도 확인합니다. 과거 기본 폴더에 남아 있는 다른 계정과 혼동하지 않으며 실행 중인 tmux/Claude 작업을 조작하지 않습니다.
- 원격 사용량은 Claude Code 자체가 사용하는 읽기 전용 `https://api.anthropic.com/api/oauth/usage`에서 조회합니다. 공개 안정 API가 아니므로 Claude 업데이트에 따라 호환성 보완이 필요할 수 있습니다. 해당 서버의 Claude 인증을 서버 안에서만 사용하고, 토큰·자격 증명·대화 내용은 Mac으로 전송하지 않습니다. 인증 갱신이나 로그인을 대신 수행하지 않습니다.
- 3분 간격으로 조회하고 수동 새로고침도 최소 60초 간격을 적용합니다. 429 응답에서는 재시도 대기 시간을 지킵니다. 성공한 최근 수치는 서버의 Notchwave 전용 파일에 비공개 권한으로 보관합니다.
- Claude 자체의 `cachedUsageUtilization`이 있다면 현재 계정 ID와 일치하고 한 시간 이내인 경우에만 이전 조회값으로 활용합니다. 계정 전환이나 조회 도중 인증 변경을 감지하면 이전 계정의 값을 버립니다.
- 원격 사용량 조회는 임시 읽기 도구를 SSH로 실행하며 Claude 설정이나 알림 훅을 수정하지 않습니다. Mac에는 서버별 계정·한도 결과를 메모리에서 관리합니다.

로컬 Claude는 기존 공식 상태 표시줄 연결을 사용합니다. **Claude Code 2.1.251 이상**에서 상태 표시줄의 `rate_limits` 데이터를 받아 계정 ID와 함께 저장하며, 첫 대화 이후 갱신됩니다. 기존 상태 표시줄 명령과 다른 설정은 보존합니다. 로컬에서 모델별 한도를 확인한 최근 `/usage` 캐시가 있으면 같은 계정에 한해서 함께 표시합니다. 로컬 OAuth 토큰이나 키체인은 조회하지 않습니다.

## 미리보기와 빌드

메뉴에서 **미리보기 창 열기**를 선택하면 예시 데이터로 네 탭을 확인할 수 있습니다. Glass/노치 전환, 접기/펼치기, 재생 표시와 배터리 알림도 확인할 수 있습니다. 예시 모드는 실제 기기·계정 잔량을 바꾸지 않습니다.

Apple Silicon Mac과 macOS 26 SDK를 포함한 Command Line Tools가 필요합니다. 실행 대상은 macOS 13 이상입니다.

```sh
bash build.sh
bash scripts/test.sh
build/Notchwave.app/Contents/MacOS/Notchwave --diagnostics
build/Notchwave.app/Contents/MacOS/Notchwave --render /absolute/path/preview.png --glass
```

프로젝트 폴더에서 실행하면 앱은 `build/Notchwave.app`에 생성됩니다. 다른 위치에 빌드하려면 `bash build.sh /absolute/path/Notchwave.app`처럼 경로를 지정합니다.

설치된 기본 SDK가 실험 버전이라 SwiftUI 컴파일러 확장이 누락된 경우 `NOTCHWAVE_SDK_PATH`에 설치된 macOS 26 SDK 경로를 지정해 빌드할 수 있습니다.

정적 미리보기는 예시 배경을 사용합니다. 실제 바탕화면을 굴절·혼합하는 Liquid Glass 효과는 실행 중인 앱에서 확인할 수 있습니다. 현재 앱은 이 Mac용 로컬 서명을 사용합니다. 재빌드 뒤에는 Spotify·캘린더 권한 재승인이 필요할 수 있습니다. 배포하려면 서명·공증과 액세서리 API 호환성 검토가 필요합니다.

## 검증 범위

자동 검사: 기존 Spotify·노치·캘린더 검증과 캡슐 크기·클릭 영역, 배터리 임계값·충전·재알림, 사용량 파싱, Claude 연결 설정 보존·복구와 캐시 최소화를 포함합니다.

실제 외장 LG 디스플레이에서 Glass 캡슐과 펼친 화면, 시스템 위젯의 여섯 기기 잔량, Bose 헤드폰의 50% 알림, 실제 Codex 계정 사용량을 확인했습니다. 캘린더에 임의의 실제 일정은 만들지 않았습니다. 원격 Claude는 실제 SSH 서버에서 로그인 환경에 따른 계정 선택과 5시간·주간·모델별 주간 사용량을 확인했습니다. 로컬 Claude 상태 표시줄 경로는 별도로 최신 CLI와 첫 응답 이후 확인해야 합니다.
